### ⚠️ Toolchain trap discovered during account verification — read before running `tsc` again
`node_modules/typescript` in this repo had gotten pinned to **7.0.2** (a Go-based rewrite with materially different module-resolution defaults) via a stray `package.json`/`package-lock.json` a prior session had added. Running the resulting `./node_modules/.bin/tsc --noEmit` produced **~630 bogus `TS2305: has no exported member 'View'/'Text'/...`** errors across every app — not real bugs, a TS7 resolution incompatibility with this project's `eitri-luminus` path-mapped `.d.ts`. Confirmed by diffing against `npx -y -p typescript@5 tsc --noEmit -p tsconfig.json` (the command the `eitri-typescript-migrate` skill actually mandates), which dropped the count to the real ~53-57 errors below. **Resolved for good:** the user confirmed this project should never have `package.json`/`package-lock.json`/`node_modules` — both files were `git rm`'d and `node_modules/` deleted; `npx -y -p typescript@5 tsc --noEmit -p tsconfig.json` re-verified working with none of those present. This is now the permanent, only supported type-check command, documented in `AGENTS.md`. **Always use it — never a local/installed `tsc`.**

Fixed two real bugs surfaced by the TS5 check while verifying account: `shared/src/hooks/useBiometricLogin.js`'s JSDoc only annotated `resolveContactKey`, which made TS infer the entire destructured parameter as type `Function` for every caller (`account/SignIn.tsx` and `home/Home.tsx` both hit `'doLogin' does not exist in type 'Function'`) — fixed by writing complete `@param` tags. `account/views/Wishlist.tsx` used `<Text>` several times without importing it from `eitri-luminus` (would have crashed on real device, not just a type gap) — added the import. Also completed `home/ProductCard.tsx` with an accepted-but-not-yet-rendered `siblings?` prop (its swatch UI depends on the still-JS `MetalSwatches`, a Phase 4 item), fixed `home/types/vtex.ts` (`VtexCartItem` was missing `uniqueId`, making a `?? item.id` key expression resolve to `unknown`), fixed a `void`-vs-`VtexCart` cast in `home/providers/LocalCart.tsx`, and replaced a non-existent `orientation` prop on `View` in `home/views/ProductCatalog.tsx` with a `flex flex-col` className.

**Resolution approach per file:** `git diff main-side` conceptually = look at the `>>>>>>> main` block vs `<<<<<<< HEAD` block already inline in the file; reapply main's logical change (new prop, bug fix, new import, new JSX) into our typed side, keeping our types/casts/fixes. Do NOT blindly take "theirs" — main's `.jsx` is untyped and may reintroduce bugs we already fixed. After resolving each file, remove the conflict markers, `git add` it, and periodically run `./node_modules/.bin/tsc --noEmit -p tsconfig.json`.
